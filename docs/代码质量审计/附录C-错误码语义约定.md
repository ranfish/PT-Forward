# 附录C 错误码语义约定

- **状态**：生效（随 04-API输入契约与一致性 整改建立）
- **日期**：2026-11-24
- **来源**：[04-API输入契约与一致性](./04-API输入契约与一致性.md) §3.3/§3.4 落地
- **适用范围**：`internal/api` 新增/修改错误响应；存量 40001/50000 不全量重编（04 篇 D4 定案）

## 1. 双层语义

| 层 | 表达 | 稳定性要求 |
|---|---|---|
| **HTTP status** | 协议语义（400 参数错/401 认证/404 不存在/405 方法/409 冲突/5xx 服务端） | 稳定——调用方可按 status 分支 |
| **业务 code** | 可分支的业务/校验语义（如 50201 云端连接/50203 下载失败） | 新增不复用模糊码承载新语义 |

## 2. 现状重载（已知·不全量改）

- `40001`：decode 失败 + 405 + 大量业务 BadRequest（233+ 处）——历史形态·保留。
- `50000`：通用服务端错误——粗粒度·保留。

## 3. message 契约（D1 定案落地）

1. **5xx 对外 message 固定稳定文案**——不拼 `err`（`fmt.Sprintf("%v", err)` 禁止出现在 message）。
2. **原始 err 只写服务端日志**（zap·op+关键标识+err——附录B 字段约定）。
3. 稳定文案统一带「请查看服务端日志」尾注（用户排障指引）。
4. `detail` 字段同样是客户端可见通道——**不透传原始 `err.Error()`**；确需细节时返回受控非敏感说明。
5. 4xx 文案本刀不动（业务校验语义·04 域外）。

## 4. 新增响应规则

- 新接口禁止复用 40001/50000 承载新语义——用可区分 code（如既有 50201/50202/50203 先例）。
- 改 code 前先确认前端是否依赖（grep `web/src` 硬编码匹配）。
- 405 继续走 `methodNotAllowed()` 单点（code 40001 历史形态保留）。
