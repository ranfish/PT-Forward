## 3. 重点发现

### 3.1 EventBus 停机排空缺位（P1·01 篇移交确认）

**证据**：
- `internal/pusher/eventbus.go:68` `Close()` 存在但全库零调用（dispatch goroutine 生命周期 = 进程生命周期）。
- `Publish`（:55-66）select-send 无 closed 守卫——**Close 后 Publish = closed channel send panic**（当前未触发·但是接线 Close 的第一陷阱）。
- 停机时 buffer（256）内未消费事件直接随进程丢失，无排空窗口。

**建议**：
- 停机序：`srv.Shutdown` 完成后（HTTP 停·新 Publish 源头枯竭）再 `Close`；dispatch `range` 自然退出即排空完成。
- Close 前置守卫：`atomic.Bool` closed 标志，Publish 见 closed 直接丢弃+Warn（消除 panic 陷阱）。
- 可选：Close 后限时 join dispatch（`done chan`+超时）作停机观测点。

### 3.2 seeding flush/free_end 残留 ctx（P2·01 篇移交确认）

**证据**：
- `internal/seeding/flush.go:35` `flushContext` 结构**无 ctx 字段**——`buildFlushContext(ctx,…)` 收 ctx 但不载入；`collectCandidates(fc)` 内 ：249 assume_free 回填只能用 `context.Background()`。
- `internal/seeding/free_end.go:108` 免费到期 timer 回调 `WithTimeout(Background,30s)`；`StopAll`（:80-87）只 `t.Stop()` 停未触发 timer——**已触发回调在途最长 30s 自界**（Engine.Stop 不等待）。

**建议**：
- flushContext 加 ctx 字段（buildFlushContext 载入·collectCandidates 消费）——纯结构穿透·一处生产点一处消费点。
- free_end 回调改派生 rootCtx（Engine 已有·刀4 单源）或维持 30s 自界（可接受：单行 DB 更新·幂等）——实施时二选一定案。

### 3.3 StartObservingCleanup 无停机通道（P2·新发现）

**证据**：
- `internal/api/publish_torrents_handler.go:336` `go func(){ Sleep(5min); cleanup; ticker 24h; for range ticker.C {…} }()`——Background·无 ctx·无 stop·无 wg。

**风险**：停机时在途清理继续跑（IO 扫描+删文件）；无 join 点（进程退出即死·中断窗口=文件操作半途）。

**建议**：挂 handler baseCtx（刀3 已有）：ticker select 加 `case <-h.baseCtx.Done(): return`；首段 5min sleep 改 `select { case <-time.After(5min): case <-h.baseCtx.Done(): return }`。
