## 一、项目定位

**PT-Forward** = 综合 PT（Private Tracker，私有种子站点）种子管理平台。Go 后端单二进制 + Vue3 前端（Go embed），覆盖 **RSS 刷流 / 普通下载 / 跨站转载发布 / 辅种 / 转移 / 截图发布** 全链路。

- **支持**：5 种站点框架（NexusPHP / UNIT3D / GazellePW / M-Team / 自研）共 116 站；qBittorrent + Transmission 双下载器；4 种下载器角色（seeding/download/source/reseed）。
- **部署**：NAS / VPS / Docker，SQLite(WAL) 或 MySQL，单二进制 + OTA 热更新。
- **差异化**：三层辅种引擎（L0 pieces_hash + L1 云指纹 + L2 搜索验证）+ 评分刷流 + 21 步发布管线，工程深度（背压/缓存/降级链/Dupe 策略/生命周期）领先 `examples/` 全部同类项目。

## 二、架构全景

### 2.1 启动流程（`cmd/pt-forward/main.go`）

`var version = "dev"` 由 `-ldflags -X` 注入（`main.go:72`）。初始化严格按依赖链，前序失败即 `os.Exit(1)`：

1. flag 解析（`-config` / `-version` / `-reset-password`）
2. Logger：4 core 组合（stdout + 按日轮转文件 + error 独立文件 + SSE 广播），经 `util.NewSanitizerCore` 脱敏（`main.go:696-737`）
3. DB：`initDB`（sqlite WAL / mysql），连接池从 config（`main.go:789`）
4. Schema：`model.AutoMigrate` → `dbpkg.RunMigrations`（数据迁移）
5. 加密：`initEncryption`（`main.go:850`）—— 优先 config.yaml 的 `encryption_key`，缺失自动生成；`crypto.RegisterCallbacks` 在 GORM Create/Update/Query 钩子透明加解密
6. WriteQueue（sqlite 缓冲 256 / mysql 透传）+ MemoryMonitor（按 `cfg.Memory` 限流）
7. `httpclient.Init` + `metrics.Init`
8. Auth：JWT HS256（access 30min / refresh 7d，bcrypt cost 12）+ `EnsureAdminUser`
9. `setting.SeedDefaults` + audit.Logger（异步 channel）+ site seed（白名单设计 §30.6）
10. 域名限流：从 sites 表 `MaxConcurrent` 推导 `httpclient.GlobalLimiter`（`main.go:198-217`）
11. **核心引擎构造 + 依赖注入**（大量 `SetXxx`）：eventDispatcher / adapterFactory / siteProvider / clientManager / rssEngine / filterEngine / reseedEngine / publishPipeline / seedingEngine / imageHostMgr / iyuuService / cloudFPService / fpRepo / completionWatcher
12. WebSocket Hub + Freeze 事件订阅（login_redirect 触发 cookiecloud 即时同步）
13. Dispatcher 路由：RoleSeeding→seedingEngine、RoleDownload/RoleSource→publishPipeline（`main.go:386-392`）
14. Router + HTTP server（`/healthz` `/metrics` + SPA fallback，中间件 `Metrics → RequestLogger`）
15. 定时任务 `registerSchedulerTasks`（见下）+ reseed 调度 + injection consumer
16. 后台引擎 Start：`clientManager.LoadClients → seedingEngine.Start → eventBus.Register → rssEngine/reseedEngine/completionWatcher.Start → downloadSyncer.Run → taskRegistry/syncManager/sideLoadMgr.Start`
17. Graceful shutdown（`main.go:566-592`）：SIGINT/SIGTERM → 60s 内逆序停

**定时任务清单**（`registerSchedulerTasks`，`main.go:977-1134`）：client_ping(`*/5`)、publish_pending/groups(`*/30`/`*/60`)、publish_lifecycle/seeding_confirm(`*/30`/`*/15`)、seeding_cleanup(`0 */6`)、seeding_auto_delete/traffic_stats(`*/30`/`*/10`)、rss_disk_budget_expire/recheck_waiting(`*/5`/`*/15`)、cookiecloud_sync(`*/5`)、rss_cleanup_old_seen/traffic_data_cleanup(`0 3 * * *`)、site_stats_sync(`0 */6`)、seeding_free_wait_check(`*/15`)、traffic_hourly_aggregate(`0 *`)。

## 三、核心业务链路

### 3.1 RSS→刷流/下载链路（§55 系列，路径 A 统一引擎）

```
rss.fetchOnce(engine.go:551)
  → IsSeen 去重(repository.go:72，只认 pushed/blocked)
  → detectHRAndDiscount(:1072，并发2，8s/种，5min cache)
  → MarkSeen("seen")(:867)
  → eventBus.Publish(PushedEvent)(eventbus.go:41，buf256 满即 drop)
  → seedingEngine.OnPushed(consumer.go:42，按 LoadActiveClientConfig 过滤)
  → pendingEvents(buf1000 满即 drop)
  → consumeLoop(30s ticker)(:61)
  → scoreAndPush(:85) 按 (clientID,subscriptionID) 分组
  → scoreAndPushForClient(:104)
       LoadActiveClientConfig(:30) 先查 seeding_client_configs 退化 download_client_configs
       活动时间窗口 + MaxActive + 磁盘保护前置过滤
       按 role 决定评分(:148)：seeding→CalculateScore，否则 Score=1.0 顺序推送
       sort desc → topN → pusher.Push
  → pusher.Push(pusher.go:93)：CheckExists → DetectDiscount 复检 → HR 保护 → DownloadTorrent → AddFromFile
  → createRecordFromPush(:373)：OnConflict DoNothing + 回写 rss_torrent_seen.status="pushed"(:464) ← §55.5 P1
  → refreshMaindataLoop(10s)(:450)：周期 evaluateRecord / executeCleanup
```

**关键**：role=seeding 与 role≠seeding 共用同一 EventBus 和 seedingEngine，仅在 `scoreAndPushForClient:148` 按 role 分流（seeding 评分挑种子，非 seeding 顺序推送）。

### 3.2 辅种链路（reseed，独立体系，不走 RSS）

```
reseed.RunTask(engine.go:1164) 由 scheduler 周期触发
  → 列源下载器所有种子 → preloadFingerprints/piecesHashCache/cloudFP
  → findCandidates(:1560) 三层匹配：
       L0 pieces_hash API（站点远端，零配额）+ verifyL0Size 二次校验
       L1 云指纹（PT-IDX，含 PiecesHash/TotalSize/FileCount/LargestFile/FileTree/FilesHash）
       L2 搜索验证（matchLayer2SearchVerify：标题截断→小组名过滤→大小匹配，confidence=0.95）
       可选 IYUU（EngineMode=IYUUCloud）
  → SaveMatch(status=matched) → StartInjectionConsumer(:245) 后台 CAS matched→injecting 两阶段注入
```

辅种负向缓存 `SetNegativeCache` 168h；熔断 `IsDomainCircuitOpen` 防站点故障。

### 3.3 跨站转载链路（publish）⚠️ 当前双重断裂（§55.7）

`publishPipeline.OnPushed(consumer.go:12)` 要求 `event.Role ∈ {download,source}`，但 RSS 发 PushedEvent 时**不设 Role**（engine.go:950）→ guard 永真 return；路径 B 入口因生产订阅都有 ClientID 几乎不走。**`publish_candidates` 表生产为空，21 步管线代码完整但入口未接线**。

**接手重点**：publish 管线是 PT-Forward 相对 `examples/` 所有项目（Upload-Assistant/gg-bot/easy-upload）的最大优势，**待激活而非重建**。

### 3.4 关键状态机

**rss_torrent_seen.status**（`repository.go:72` IsSeen 只通过 pushed/blocked）：
- `seen`（MarkSeen 写入）→ 仍可被下轮重投（容错）
- `pushed`（createRecordFromPush 回写）→ 永久去重 ✅
- `blocked`（compliance 命中）→ 永久去重

**seeding_torrent_records.status**：
- 入口 `pending` 或直接 `seeding`（createRecordFromPush:401）
- `seeding` ⇄ `paused_free_end` / `paused_rule`（磁盘保护）
- `seeding` → `transferring`（checkAutoTransfer:3038 CAS）→ 成功删 record / 失败 `revertTransferring:3105`
- `seeding` → `deleting` → `deleted`（syncStaleRecords:54）
- **启动时 `transferring` 全部回退 `seeding`**（engine.go:347，防重启卡死）

**download_task**：downloading/completed/paused/error/deleted；transfer_status：none/transferring/transferred/partial/failed。

### 3.5 评分算法（`seeding.CalculateScore`，scoring.go:53）

```
demandScore  = Leechers/Seeders（Seeders=0 时 99999；都 0 时 0）
uploadValue  = 折扣系数（Free=1.0, 2xFree=2.0, 2xUp=1.5, 2x50=1.75, 百分比档 0.625~0.875, None=0.5）
recencyFactor = 1/(1 + AgeHours/HalfLifeHours)（半衰期默认 2h）
EffectiveScore = demandScore × uploadValue × siteWeight × recencyFactor
```
MinScore 过滤在 `scoreAndPushForClient:180`。零值防护：HalfLife≤0→2，SiteWeight≤0→1。配置来自 `RSSSubscription.ScoringConfig`（gorm embedded，§55.10 曾有读写脱节 bug 已修）。

**清理评分**（`CalculateCleanupScore:120`，独立算法）：`0.3*seedScore + 0.3*speedScore + 0.2*uploadValue - hrPenalty - 0.2*diskFactor`，配 `ShouldCleanup(minScore=0.3, minAge=48h)`。

### 3.6 删种/转移/级联协调

- **删种规则** `rule.MatchRule`（evaluator.go:213）：expr-lang 表达式或条件+逻辑（and/or）；`ExprEnv` 暴露 ~40 字段；`FitTimer` 实现"持续命中 N 时间才删"。
- **级联删** `companion.PlanDelete`（companion.go:88）：按 `REPOST_*` tag 或 (SavePath+Name) BFS 找伴随种子（深度 1）；`deleteCompanions=false` 但确有伴随 → 强制 `DeleteData=false`（防孤儿数据）。
- **转移公共函数** `client.TransferTorrent`（§55.12）：ExportTorrent → GetTorrentByHash → MapPath → AddFromFile，**不删源**。
- **两级转移协调**（关键坑）：
  - 订阅级 `transferRecord`(engine.go:3053)：record.AutoTransfer + Progress≥1.0 触发，多目标，CAS 防并发
  - 下载器级 `syncer.processTransfer`(syncer.go:377)：download_task completed + 下载器 transferTargetId，单目标兜底
  - **协调**：syncer 开头查 `seeding_torrent_records.auto_transfer=true AND status IN ('seeding','transferring')`（syncer.go:380），命中 skip 让订阅级优先

### 3.7 角色分流机制（§55.13-§55.15）

四种 role（dispatcher.go:16）：`seeding` / `download` / `source` / `reseed`。
- **演进**：原路径 B（TorrentDispatcher 按 role 分发）已退居 side-load 回放专用；生产全走路径 A 统一由 seedingEngine 管，靠 `record.Role` 字段在 `scoreAndPushForClient:148` 内分流。
- **地址唯一原则**（§55.14）：同一物理下载器（协议+地址+端口）只能添加一次，一个 role → 一个体系 → 消除双轨。
- **配置加载统一入口**：`LoadActiveClientConfig`(consumer.go:30) 先查 `seeding_client_configs`，未命中查 `download_client_configs` 并经 `downloadConfigToSeeding` 适配。`OnPushed`/`scoreAndPushForClient`/`handleTriggerClient` 全部复用。
- **syncer 去重叠**（syncer.go:307 importTask）：hash 已被 seeding record 管理则跳过导入 download_task。

### 4.2 凭证安全

- **加密**：AES-256-GCM，PBKDF2(100000 轮, SHA256) 派生密钥（`crypto/crypto.go:46`）。密文前缀 `enc2:`（v2）/`enc:`（legacy）。
- **GORM 回调自动加解密**（`crypto/callbacks.go:12`）：扫描 struct tag `encrypted:"true"`（含 embedded 递归）。受保护：Site.{Passkey,Cookie,APIKey,BearerToken,AuthKey,AuthHash,RSSKey}、ClientConfig.Password、CloudFPConfig.APIToken、IYUUConfig.Token、CookieCloudConfig.Password、Notification.Config、SiteConfigOverride.FieldValue。
- **铁律**：日志不得出现 cookie/passkey/apikey/token（SanitizerCore 自动脱敏为 `***`）；站点凭证云端存储同样加密。

## 五、站点适配器

### 5.1 四框架对比

| 框架 | 采集策略 | 认证 | HashStrategy | SideLoading | pieces_hash |
|---|---|---|---|---|---|
| **NexusPHP**（最普遍，97+ 站）| HTML 正则 scrape 详情页 | Cookie+Passkey / Bearer(1.9+) / X-Passkey | `guid` | 否 | ✅ 1.8.5+ `POST /third-party/pieces-hash` |

### 8.2 认证与中间件

JWT HS256，Access 30min / Refresh 7d（持久化 settings 表，重启不丢），bcrypt cost 12，登录限流 5 次/5min。仅 admin 单用户。中间件链：CORS → Recovery → RateLimit(global 600/write 200/download 50 per min) → JWTAuth → SecurityHeaders → MaxBodySize。外层全局 `Metrics()` + `RequestLogger()`（X-Request-ID 8 位）。

**审计缺口**：`auditLog()` 覆盖 auth/site/rss/seeding/client/cookiecloud/settings/system 写操作；**publish/reseed/download 业务写操作未覆盖**（接手可补）。

### 8.3 前端架构（`web/src`）

Vue 3.5 + **Ant Design Vue 4.2** + Pinia 3 + Vue Router 4 + Axios + ECharts 6 + vue-i18n 9，Vite 8 构建。HTTP 封装 `api/client.ts`（baseURL `/api/v1`，401 自动 refresh 单飞），按业务域拆 30 个 api 文件。路由 40+ 页面（`router/index.ts`），与后端 API 域一一对应。i18n `locales/{zh-CN,en}.json`（各 ~1430 行）。

**embed 铁律**：`frontend/spa.go:11` `//go:embed all:dist`。Go 编译 embed 的是 `frontend/dist`（构建产物），不是 `web/src`（源码）。**正确链路**：`vite build`（产物 web/dist）→ `cp -r web/dist frontend/dist` → `go build`。三步缺一不可，**跳过 vite build = 前端改动不生效**。

### 8.4 OTA 热更新（`internal/api/update_handler.go`）

检查 GitHub Releases → 按 GOARCH 选 asset → 后台下载到 `.pt-forward.new` → **SHA256 强制校验** → `--version` 验证可运行 → 备份 `.bak` + 原子 rename → `os.Exit(0)`。

**为什么 systemd 必须 `Restart=always`**：OTA 走"正常退出（exit 0）"路径，`on-failure` 不重启正常退出进程 → OTA 后服务永久停止。`Restart=always` 才会在 exit 0 后拉起新二进制。

## 九、PT 生态核心概念词典

| 术语 | 定义 |
|---|---|
| PT (Private Tracker) | 私有 BT 站点，需注册，基于 passkey 统计上传/下载，有分享率门槛 |
| passkey | 用户唯一密钥（32 位 hex），嵌 tracker announce URL，站点凭此识别身份计流量。泄露=他人可冒刷流量 |
| torrent | bencode 元数据文件，含 `info` 字典（文件名/大小/pieces 分片哈希）+ announce |
| info_hash | SHA1(info 字典)，40 位 hex，**种子级唯一**（同内容不同 tracker/文件名会产生不同 info_hash） |
| **pieces_hash** | SHA1(info.pieces 字段)，**内容级唯一**，跨站同内容一致，NexusPHP 1.8.5+ 引入，**辅种金标准** |
| free/2x/50%/2XFREE | 下载量不计 / 上传双倍 / 下载 5 折 / 双免；另有 VIP 专属促销 |
| HR (H&R, Hit and Run) | 下载后必须做种达规定时长/分享率（常见 72h / ratio≥1.0），否则警告/封号 |
| 辅种 (cross-seed) | 用已下载数据在另一站同内容种子做种，只链接不重下，提升分享率 |
| 刷流 | 自动抓免费/促销种子→下载→做种，刷上传量升用户级 |
| 转载（跨站搬运）| 从 A 站下载→重打 tracker/补字段→发布到 B 站（注意禁转/独占标签） |
| 官组/压制组 | 站内官方组（享双倍上传/禁转保护）；压制组重编码原盘（DON/WiKi/CMCT 等） |
| 种距 | 同一资源在不同站的发布时间差（影响先发权） |
| 分享率 (ratio) | 上传/下载，PT 站常要求 ≥1.0 否则封号 |
| 魔力/积分/银两 | 站点虚拟货币（憨豆/咖啡豆/灵石等），做种/签到获得，可买上传量/免 HR |

**7 种站点认证类型**：A. NexusPHP Cookie（`c_secure_*`，80+ 站）/ B. M-Team apikey（`x-api-key`，严禁调 /login//admin//apikey 会封号）/ C. Rousi Passkey Bearer（`Authorization: Bearer {passkey}`）/ D. UNIT3D Cookie+CSRF / E. TNode Cookie+CSRF（`x-csrf-token`）/ F. Gazelle session cookie（可选 `Authorization: {apikey}` raw）/ G. Generic 定制。

## 十、同类产品对照与借鉴

### 10.1 辅种类（PT-Forward 三层引擎的渊源）

| 项目 | 语言 | 核心机制 | 借鉴价值 |
|---|---|---|---|
| **cross-seed** | TS | 4 维决策（releaseGroup/resolution/source/proper-repack）+ 3 匹配模式（Strict/Flexible/Partial 分片覆盖率）+ Torznab | ★★★★★ 决策引擎 |
| **Graft** | Rust | 本地指纹 5 字段（total_size/file_count/largest_file/files_hash）+ 5 级置信度（ExactMatch/High/Medium/Low） | ★★★★★ 本地指纹 |
| **ptdog** | Go | Scanner→Querier→Seeder 生产者-消费者，pieces_hash 批量 POST | ★★★★★ 技术栈一致可直接参考 |
| **IYUU/IYUUPlus** | PHP | 云端 info_hash 匹配 85+ 站，6 事件钩子，三态（Default/Success/Fail） | ★★★★★ 事件系统+状态枚举 |
| **Reseed-Puppy** | PHP | pieces_hash 批量（100/批）+ info_hash 反查 qB | ★★★ 落地实现 |
| **PTNexus** | Go+Vue3+Wails | 转种发布工作流 + 禁转/限转/分集检测 + 网段做种 guard | ★★★★ 发布规则 |

**PT-Forward 辅种引擎对照**：L0 多了 size 二次验证（fail-closed）；L1 字段最全（同时支持 Graft 式 5 字段 + cross-seed 式 FileTree）；L2 是兜底但**未引入 cross-seed 4 维预过滤**（可补 `RES_STRICT_REGEX` 等正则降低误判）。FilesHash 用 SHA-256（与 Graft 的 SHA-1 不兼容，PT-IDX 同步需注意）。

### 10.2 刷流/转发类

| 项目 | 核心机制 |
|---|---|
| **rflush** | 两轮过滤（RSS 预筛 + 详情增强复筛）+ 域名级 FIFO 限速 + 429 自动冻结 + SSE 实时日志 + activeTimeWindows（支持跨天）+ 删种 7 规则 AND/OR |
| **ARSS+ADTU** | 七层过滤（free→time→HR→大小→关键词→类型→分辨率）+ queue/send/num_per_turn 背压 + 主从架构 + 站点级禁转 TOML |
| **vertex** | 五类规则（Rss/Race/Link/Delete）accept/reject 按 priority + sameServerClients 同机聚合限速 + addCountPerHour 背压 |
| **hdapt** | MT 编码字典映射（数字→标准 codec）+ 强制 reannounce（2min）+ 磁盘保护 low_space 模式 + 配置每轮热重载 |
| **autobrr** | IRC 抓种 + filter 30+ 维度 + 首匹配 + RejectReasons 结构化 + ExternalFilters webhook |

## 附录 A：编码规范 Checklist（`docs/33`）

- [ ] **目录**：`internal/model/` 只放 struct/interface（零业务逻辑）；新增 struct 先登记 docs/31 §33.1 再写代码
- [ ] **命名**：包全小写单单词；文件 snake_case；struct/interface PascalCase；DB 表复数蛇形；接口 -er/-Provider 后缀
- [ ] **Context**：所有跨函数调用首参必传 ctx（§33.2 canonical 签名为准）
- [ ] **错误**：底层返回 AppError 或 `fmt.Errorf("%w", appErr)`；Service 层禁裸 `errors.New`；Provider Get 返回 `(nil, ErrNotFound)` 而非 `(nil, nil)`；**禁止 `_ = op()`**
- [ ] **并发安全**：GORM 模型值接收者；含 `sync.*` 的运行时 struct 必须指针接收者（go vet copylocks）；运行时 struct 字段在 Start() 前赋值，之后不可变
- [ ] **nil 防御**：`*time.Time` 解引用前必 nil 检查（用 TimeSince）
- [ ] **GORM**：写走 DBWriteQueue.Execute()，读直接用 db；GetSiteConfig() 每次返回深拷贝；API 禁暴露 uint 主键 ID（用 domain/name）
- [ ] **SQL**：禁 `db.Raw` + `fmt.Sprintf` 拼用户输入，必须参数化 `?`
- [ ] **Discount**：禁硬编码 `IsFree=true`，用 `event.Discount.IsFree()`
- [ ] **凭据**：AES-GCM 由 GORM hook 自动处理，编码只读写明文
- [ ] **注释**：接口方法必有 godoc；复杂逻辑注释"为什么"；引用 `// §33.1.87`
- [ ] **测试**：`xxx_test.go` 同目录；集成测试 sqlite 内存 `file::memory:?cache=shared`；CI 启用 `-race`；不 mock GORM
- [ ] **同步清单**：改 struct 同步 5 处（model/§33.1、config、DTO、migrate.go、docs/31 §33.8）
