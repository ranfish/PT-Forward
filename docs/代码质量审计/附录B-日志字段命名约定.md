# 附录B 日志字段命名约定

- **状态**：生效（随 03-错误处理与可观测性 整改建立）
- **日期**：2026-11-24
- **来源**：[03-错误处理与可观测性](./03-错误处理与可观测性.md) §2.5/§2.6 落地
- **适用范围**：`internal/` 新增/修改日志语句；存量不机械替换（触达相关文件时顺手收敛）

## 1. 站点字段语义

| 字段 | 语义 | 使用场景 |
|---|---|---|
| `site` | 当前操作的主站点（默认/单站语境） | 采集/探测/单站操作 |
| `target_site` | 发布/转移的目标站 | 发布链/站批 |
| `source_site` | 资源来源站 | 发布链/辅种（与 target 成对出现） |

- 单站语境用 `site`；有方向（源→目标）时用 `source_site`/`target_site` 成对。
- 禁止 `siteName`/`siteName` camelCase 形态（存量 1 处触达时收敛）。

## 2. 通用规则

1. **snake_case**：日志字段名一律 snake_case（与 JSON 字段规范同族）。
2. **标识字段惯用名**：`info_hash`/`pieces_hash`/`torrent_id`/`task_id`/`client_id`/`client_uid`/`batch_group_id`——与 DB 列名/模型字段对齐。
3. **错误字段**：一律 `zap.Error(err)`（不是 `zap.String("error", ...)`）。
4. **op 字段**：同类多操作共用日志语句时加 `op`（create/update/delete/reload）区分。

## 3. `_ =` 分级约定（审计 03 §2.6 落地）

| 级别 | 形态 | 处理 |
|---|---|---|
| **可忽略** | `Close`/`Drain`/纯展示写入/已知格式解析 | 上下文明显或加注释 |
| **应日志化** | 审计落库/调度注销/缓存刷新/非关键 DB 写 | Warn+定位字段 |
| **应返回/重试** | 影响业务正确性/数据一致性/状态机推进的写入 | 返回错误或重试 |

- 评审重点扫副作用调用：`Create/Save/Update/Delete/Exec/Reload/Unregister`。

## 4. 5xx 日志约定（审计 03 §2.3 落地）

- handler 返回 5xx 前记录业务日志（`op`/关键标识/`err`）——中间件请求级日志只知状态不知根因。
- 4xx 视噪音决定；对外 message 稳定化属 04 篇（错误契约）。
